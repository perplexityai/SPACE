# Third-party images that GitHub CI takes from this repository's GHCR mirror.
#
# Anonymous public.ecr.aws pulls from GitHub-hosted runners fail with
# "toomanyrequests: Data limit exceeded" once the runners' shared egress has
# used up its quota, and retrying does not help. Main CI copies each image
# listed here to GHCR once, and GitHub CI takes it from there, falling back to
# the source. No Dockerfile changes, and builds outside GitHub CI, such as
# the private pipeline's, never read this list. See ci/scripts/mirror-images.sh.
#
# One image per line: its name exactly as the Dockerfile FROM line, ARG
# default, or tool writes it; the digest of its linux/amd64 image manifest;
# its GHCR destination; and, optionally, another repository that serves the
# same digest. Pin the linux/amd64 manifest rather than the multi-platform
# index: the runners are x86_64, and copying an index would pull every
# platform through the rate-limited source.
# `docker buildx imagetools inspect <name>` lists each platform's digest.
#
# The copy is by digest, so its content cannot depend on which repository
# served it. Main's copy hits the same public.ecr.aws data limit, so each
# public.ecr.aws image whose digest Docker Hub also serves names that
# repository too. Canonical's public.ecr.aws/ubuntu/ubuntu build has no Docker
# Hub twin.
#
# Dockerfiles carry no `# syntax=` directive. A build context cannot replace
# the frontend image one names, so BuildKit would pull it from Docker Hub
# before every build; the daemon's built-in frontend needs no pull.
